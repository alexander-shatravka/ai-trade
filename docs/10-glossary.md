# 10 — Глосарій

Мета: щоб одна й та сама річ називалась однаково в БД, в API, в UI та в розмові.
Розбіжності в термінах — головна причина того, що в схемі з'являються `status`, `state` і `stage`
для одного й того самого.

**Правило:** ідентифікатори в коді — англійською, текст для користувача — українською.

---

## 1. Сутності домену

| Українською | У коді / БД | Що це саме |
|---|---|---|
| Оголошення | `Listing` | Одиниця продажу. **Не** `Ad`, **не** `Post`, **не** `Product` |
| Товар | — | Розмовне слово для того, що описує `Listing`. Окремої сутності немає |
| Продавець | `User` (`Listing.userId`) | Не окрема таблиця — це роль, а не тип користувача |
| Покупець | `User` (`ChatThread.buyerId`) | Те саме |
| Магазин / бізнес | `BusinessProfile` | Профіль для тарифу BUSINESS |
| Категорія | `Category` | Дерево з `parentId`, 2 рівні на MVP |
| Характеристики | `attributes` (JSONB) | Значення за `Category.attributeSchema`. **Не** `specs`, **не** `properties` |
| Схема характеристик | `attributeSchema` | JSON Schema. Керує і AI-виводом, і фільтрами в UI |
| Фото / медіа | `Media` | Оригінал у S3 + згенеровані варіанти |
| Діалог / переписка | `ChatThread` | Один тред на пару «оголошення ↔ покупець» |
| Повідомлення | `ChatMessage` | |
| Відгук | `Review` | Дозволений лише після взаємного контакту |
| Скарга | `Report` | |
| Тариф | `Plan` | Дані в БД, не константи в коді |
| Підписка | `Subscription` | Зв'язок користувача з тарифом на період |
| Просування | `Promotion` | Разова платна послуга (START / PREMIUM / VIP) |
| Оцінка (платна) | `Valuation` | Поглиблений AI-звіт по дорогому товару |
| Масовий імпорт | `BulkImport` / `BulkImportRow` | Excel/CSV → каталог |
| AI-задача | `AiJob` | Аудит одного звернення до AI |
| Порада / розбір | `SellerAdvice` | Результат «чому не продається» |

## 2. AI-терміни

| Українською | У коді | Пояснення |
|---|---|---|
| AI Seller / «Продай за мене» | `ai/seller/analyze` | Головний флоу: фото → готова чернетка |
| AI Advisor / «Чому не продається» | `SellerAdvice`, `LISTING_DIAGNOSE` | Діагностика оголошення по 5 осях |
| Впевненість | `confidence` (0–1) | Реальна впевненість моделі. `< 0.6` → зупиняємо флоу |
| Невпевнені поля | `uncertainFields` | Підсвічуються в UI жовтим |
| Обґрунтування | `reasoning` | Текстове пояснення від LLM |
| Докази | `evidence` | Прив'язка твердження до конкретного `mediaId` |
| Прийняті поля | `aiAcceptedFields` | Які AI-поля користувач **не** правив. Ключова метрика якості |
| Деградація | `DEGRADED`, `X-Ai-Degraded` | Відповідь дав фолбек-провайдер, а не основний |
| Мок-провайдер | `MockProvider` | Детерміновані реалістичні дані. `AI_PROVIDER=mock` |
| Версія промпту | `promptVersion` | Напр. `vision.recognize@v4`. Дозволяє порівнювати якість |
| Ембеддинг | `embedding` | `vector(1536)`, для семантичного пошуку |
| Health score | `healthScore` (0–100) | Загальна «здоровість» оголошення в Advisor |
| Ймовірність продажу | `sellProbability` (0–100) | Прогноз, **не** гарантія |
| Прескоринг ризику | `riskScore` (0–1) | Для автомодерації: `<0.2` авто, `0.2–0.7` черга, `>0.7` блок |

## 3. Гроші та ціни

| Українською | У коді | Примітка |
|---|---|---|
| Ціна | `priceKop` | **Завжди копійки, Int.** Ніколи не Float |
| Вартість AI-виклику | `costMicroKop` | Мікрокопійки (1 коп = 1000) — виклики дуже дешеві |
| Швидкий продаж | `quickSaleKop` | Нижче медіани, 3–5 днів |
| Оптимальна ціна | `optimalKop` | Медіана. Обрана за замовчуванням |
| Максимум | `maximumKop` | Верхня межа реалістичного діапазону |
| Медіана ринку | `medianKop` | Рахується SQL, **не** питається в LLM |
| Комісія | `feeKop` | На MVP завжди `0`. Точка розширення для Етапу 4 |

**Суфікс `Kop` обов'язковий** для будь-якої грошової величини. Змінна `price` без суфікса
в code review — привід повернути на доопрацювання.

## 4. Статуси

### `ListingStatus`
`DRAFT` (створено AI, не опубліковано) → `PENDING_MODERATION` → `ACTIVE` →
`SOLD` / `ARCHIVED` (знято користувачем) / `EXPIRED` (60 днів) / `REJECTED`

### `ItemCondition` — стан товару
| Код | Українською |
|---|---|
| `NEW` | Новий |
| `LIKE_NEW` | Як новий |
| `GOOD` | Гарний |
| `ACCEPTABLE` | Задовільний |
| `FOR_PARTS` | На запчастини |

### `AiJobStatus`
`QUEUED` → `RUNNING` → `COMPLETED` / `FAILED` / `DEGRADED`

### `SubscriptionStatus`
`ACTIVE` · `PAST_DUE` (платіж не пройшов, є grace-період) · `CANCELED` (діє до кінця періоду) · `EXPIRED`

## 5. Іменування — домовленості

| Що | Правило | Приклад |
|---|---|---|
| Булеві поля | префікс `is` / `has` / `can` | `isVerified`, `hasPhone`, `canReview` |
| Дати подій | суфікс `At` | `publishedAt`, `soldAt`, `moderatedAt` |
| Лічильники | суфікс `Count` | `viewsCount`, `savesCount` |
| Зовнішні ключі | `<entity>Id` | `listingId`, `categoryId` |
| Enum-значення | `SCREAMING_SNAKE` | `LIKE_NEW`, `PENDING_MODERATION` |
| Поля БД / API | `camelCase` | `priceKop`, `aiConfidence` |
| Таблиці | `snake_case`, множина, через `@@map` | `listings`, `ai_jobs` |
| Ендпоінти | `kebab-case`, множина | `/bulk-imports`, `/saved-searches` |
| React-компоненти | `PascalCase` | `ListingCard`, `AiPricePanel` |
| CSS-токени | `--<група>-<ключ>` | `--brand-500`, `--sh-lg`, `--r-md` |

## 6. Слова, яких уникаємо

| Не кажемо | Кажемо | Чому |
|---|---|---|
| «AI визначив ціну» | «AI рекомендує ціну» | Юридично: це не експертна оцінка майна |
| «Гарантований продаж» | «Ймовірність продажу — 78%» | Прогноз ≠ обіцянка |
| «Оригінал 100%» (в AI-описах) | опис фактичного стану | Ми не можемо це перевірити |
| «Ad», «Post», «Product» у коді | `Listing` | Один термін на одну сутність |
| «price» без суфікса | `priceKop` | Див. розділ 3 |
| «Штучний інтелект вирішив» | «AI пропонує, ви підтверджуєте» | Принцип продукту: рішення за людиною |
