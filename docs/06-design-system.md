# 06 — Дизайн-система

Жива версія: **`design/design-system.html`** — відкрийте у браузері, перемикач теми у шапці.
Цей документ — правила, які з макета не видно.

---

## 1. Чотири принципи

**1. Фото — головний герой.** Інтерфейс маркетплейсу — це рамка навколо товару.
Нейтральні поверхні, стриманий колір, жодних декоративних градієнтів поруч із фотографіями.

**2. AI видно, але він не кричить.** Усе згенероване AI має однаковий маркер —
фіолетово-бірюзовий акцент. Користувач завжди відрізняє, що написала машина, а що людина.

**3. Рішення — за людиною.** Кожне AI-поле редаговане, кожна рекомендація має кнопку «змінити».
AI пропонує, людина підтверджує.

**4. Число — з поясненням.** Ціна, ймовірність продажу, health score ніколи не показуються самі.
Поруч — одне речення «чому». Інакше це магія, а магії не довіряють.

## 2. Колір

| Роль | Колір | Обґрунтування |
|---|---|---|
| Brand | фіолетово-індиговий `#6E5BE8` | Синій — банки й корпоративний софт, зелений зайнятий «еко», помаранчевий — це OLX. Індиго вільний в українському e-commerce і читається як технологічність без агресії. |
| Accent (AI) | бірюзовий `#14B8A6` | Використовується **виключно** для AI-функцій. Так користувач за пів секунди відрізняє AI-блок. |
| Neutral | холодний сірий | Теплі сірі жовтять фотографії товарів на світлому тлі. |

### Темна тема — не інверсія

```css
:root          { --primary: #6E5BE8; }   /* контраст на білому: 5.9:1 ✓ */
[data-theme=dark] { --primary: #8C7DF1; }   /* #6E5BE8 на #0A0C11 = 4.1:1 ✗ → потрібен світліший */
```

Це найчастіша помилка при додаванні dark mode постфактум: беруть ті самі бренд-кольори
й отримують нечитабельні посилання. У темній темі також **не працюють тіні** — ієрархію
тримає світлішання поверхні (`--surface` → `--surface-raised`).

Повна таблиця токенів — у `design/design-system.html`, розділ «Колір».

## 3. Типографіка

Inter з фолбеком на системний стек (на Apple-пристроях — SF Pro).

| Роль | Розмір | Вага | Трекінг |
|---|---|---|---|
| display | `clamp(2.6rem, 1.4rem + 3.6vw, 4.5rem)` | 680 | −0.035em |
| h1 | `clamp(2rem, 1.3rem + 2.2vw, 3rem)` | 640 | −0.028em |
| h2 | `clamp(1.5rem, 1.15rem + 1.1vw, 2.125rem)` | 640 | −0.024em |
| body | **0.9375rem (15px)** | 400 | −0.006em, line-height 1.6 |
| sm | 0.8125rem | 400 | — |

**Чому 15px база, а не 16.** 16px у щільному інтерфейсі маркетплейсу дає надто «повітряні»
картки — на екран влазить менше товарів. 14px уже некомфортно для довгих описів.
15px — компроміс, який використовують Linear і Stripe Dashboard.

**Максимальна ширина рядка — 68 символів (~640px).** Опис товару в дві колонки не робимо.

---

## 4. Простір, радіуси, тіні

Сітка **4pt**: `--s-1` = 4px … `--s-32` = 128px.

Радіуси зростають разом із елементом: чіпи `--r-sm` (6px) → кнопки й інпути `--r-md` (10px)
→ картки `--r-lg` (14px) → секції й модалки `--r-xl`/`--r-2xl`.
Вкладений елемент завжди має менший радіус за контейнер — інакше кути виглядають зламаними.

Шість рівнів тіней від `--sh-xs` (інпути) до `--sh-xl` (модалки) + `--sh-brand`
для головної дії. Тінь ніколи не використовується для декорації — тільки для позначення
рівня над поверхнею.

## 5. Рух

| Токен | Значення | Де |
|---|---|---|
| `--d-fast` | 120 мс | hover, focus, натискання |
| `--d-base` | 200 мс | поява карток, зміна теми |
| `--d-slow` | 320 мс | модалки, прогрес AI |
| `--e-out` | `cubic-bezier(.32,.72,0,1)` | за замовчуванням |
| `--e-spring` | `cubic-bezier(.34,1.56,.64,1)` | перемикачі, чекбокси |

`prefers-reduced-motion: reduce` вимикає всі переходи глобально. Це не опція:
для частини користувачів анімація викликає фізичну нудоту.

## 6. Ключові компоненти

### Картка товару
Найважливіший компонент продукту — його бачать частіше за всі інші разом.

- Співвідношення фото **4:3**, не квадрат: більшість фото з телефона вертикальні
  або горизонтальні, і 4:3 обрізає їх найменш болісно.
- Заголовок — рівно 2 рядки (`-webkit-line-clamp: 2`), щоб картки в сітці мали однакову висоту.
- Ціна візуально важливіша за заголовок — це перше, на що дивиться покупець.
- Бейдж `✨ AI` — у лівому верхньому куті фото, поверх зображення.
- `blurhash` як плейсхолдер — прибирає стрибок макета (CLS) при завантаженні.

### AI-панель
Відрізняється від звичайної картки градієнтною рамкою й міткою `AI` з бірюзовою крапкою.
Обов'язкові елементи: сам вивід, **обґрунтування з числами**, дія, дисклеймер (для цінових рекомендацій).

### Три цінові сценарії
Ніколи не показуємо одне число. Три картки: «Швидкий продаж» / «Оптимальна» / «Максимум»,
середня вибрана за замовчуванням, кожна з поясненням при наведенні.
Це знижує тривогу продавця: він бачить не вирок, а спектр.

### Блок «Чому не продається»
Кожна знахідка має три частини: **що** не так → **чому це видно** (конкретні числа) →
**що зробити** (кнопка). Порада без кнопки — це просто критика, і вона не працює.

## 7. Адаптивність

| Брейкпойнт | Ширина | Сітка карток |
|---|---|---|
| mobile | < 640px | 2 колонки |
| tablet | 640–1024px | 3 колонки |
| desktop | 1024–1280px | 4 колонки |
| wide | > 1280px | 5 колонок, контейнер 1180px |

**Mobile-first обов'язковий:** ≥ 70% трафіку — мобільний. AI-флоу проєктується
під великий палець: камера доступна в один тап, кнопки нижньої дії — у зоні досяжності,
жодних hover-залежних станів.

## 8. Доступність (WCAG 2.1 AA)

| Правило | Реалізація |
|---|---|
| Контраст | ≥ 4.5:1 звичайний текст, ≥ 3:1 великий. Перевірено в обох темах. |
| Фокус | `:focus-visible` — кільце 2px кольору `--primary`. Ніколи `outline: none`. |
| Розмір цілі | Мінімум 44×44 px на дотик; кнопки 32px мають прозорий padding до 44. |
| Колір ≠ єдиний носій сенсу | Статуси мають і колір, і текст. |
| Рух | `prefers-reduced-motion` вимикає переходи. |
| AI-контент | `aria-label="Згенеровано штучним інтелектом"` на AI-блоках. |
| Форми | `<label for>` у кожного інпута; помилки через `aria-describedby`. |
| Фото товарів | `alt` = заголовок оголошення, а не «фото». |

## 9. Реалізація в коді

```
packages/ui/
├── tokens.css              ← точна копія :root із design-system.html
├── tailwind-preset.ts      ← мапінг токенів у Tailwind theme
└── src/
    ├── Button.tsx  Input.tsx  Badge.tsx  Card.tsx  Chip.tsx  Switch.tsx
    ├── ListingCard.tsx
    ├── ai/  AiPanel.tsx  PriceTiers.tsx  AdviceCard.tsx  AiProgress.tsx
    └── ...
```

Токени живуть **в одному місці** — `tokens.css`. Tailwind-preset їх читає, компоненти
використовують Tailwind-класи. Змінити бренд-колір = змінити один рядок.

Компоненти будуються на **Radix UI primitives** (доступність з коробки: фокус-трапи,
клавіатурна навігація, ARIA) + власні стилі. Не беремо готову UI-бібліотеку цілком —
маркетплейс має виглядати як маркетплейс, а не як адмінка на Material.
