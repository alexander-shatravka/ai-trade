## Маршрути під задачу

**«Я вперше бачу цей проєкт»**
`AGENTS.md` → `01-product-spec.md` → відкрити `design/landing.html` і `design/app-screens.html`
→ `02-architecture.md`

**«Мені писати код»**
`AGENTS.md` → `09-implementation-guide.md` → `08-conventions.md` → далі за модулем

**«Я роблю щось з AI»**
`05-ai-architecture.md` цілком → `AGENTS.md` розділ 5 (залізні правила) → `AiJob` у `prisma/schema.prisma`

**«Я роблю екран»**
`06-design-system.md` → відкрити `design/design-system.html` → знайти близький екран у `design/app-screens.html`

**«Я додаю ендпоінт»**
`04-api-contracts.md` (конвенції) → `openapi/openapi.yaml` (описати першим) → `packages/contracts` (Zod)
→ реалізація в NestJS

**«Я додаю поле в БД»**
`03-database.md` → `prisma/schema.prisma` → перевірити, чи потрібен індекс
→ чи не ламає це `packages/contracts`

**«Мене питають про терміни, ціни або обсяг»**
`07-roadmap.md` → `01-product-spec.md` розділ 6 (монетизація)

## Правило підтримки документації

Документ і код розходяться швидше, ніж здається. Тому:

- Змінив контракт API → онови `openapi/openapi.yaml` **у тому ж коміті**.
- Змінив схему БД → онови `prisma/schema.prisma` і, якщо змінилася логіка, `03-database.md`.
- Змінив промпт → підніми `promptVersion` і зафіксуй у `05-ai-architecture.md`.
- Змінив токен дизайну → онови і `packages/ui/tokens.css`, і `design/design-system.html`.
- Змінив ціни або ліміти тарифів → це дані в таблиці `Plan`, а не код; онови також `01-product-spec.md`.
