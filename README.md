# AI Trade v2.0 — MVP

> **«Продайте будь-яку річ за 30 секунд за допомогою AI»**

Українська AI-платформа електронної комерції. На відміну від класичних дошок оголошень,
де користувач сам створює оголошення, **AI Trade створює оголошення замість користувача**:
розпізнає товар на фото, пише заголовок і опис, витягує характеристики, оцінює ринкову ціну,
покращує фотографії та прогнозує ймовірність швидкого продажу.

## Ключові архітектурні рішення

| Рішення | Чому |
|---|---|
| **Монорепо (pnpm + Turborepo)** | Спільні TypeScript-типи між Next.js і NestJS. Один PR = зміна контракту + фронт + бек. |
| **Next.js 15 App Router (frontend)** | SSR/ISR для SEO-критичних сторінок оголошень — це головний канал органічного трафіку маркетплейсу. |
| **NestJS (backend)** | Модульна DI-архітектура, з якої легко виносити модулі в окремі сервіси, коли AI-навантаження зросте. |
| **PostgreSQL + pgvector** | Один рушій для реляційних даних, повнотекстового пошуку і векторного семантичного пошуку. Без окремого Elasticsearch/Pinecone на MVP. |
| **AI як окремий модуль з провайдер-інтерфейсом** | `AiProvider` — інтерфейс. `OpenAiProvider` + `MockProvider`. Перемикання через env, без зміни бізнес-логіки. |
| **BullMQ + Redis для AI-задач** | Розпізнавання фото займає 5–15 с. Синхронний HTTP тут ламається. Черга + WebSocket-прогрес. |
| **Money як `Int` у копійках** | Жодних float у грошах. Ніколи. |
| **Feature flags для відкладеного функціоналу** | Комісія, ескроу, доставка вимкнені, але точки розширення в схемі БД уже є. |

## Швидкий старт (коли з'явиться код Етапу 2)

```bash
pnpm install
cp .env.example .env          # AI_PROVIDER=mock — працює одразу без ключів
docker compose up -d          # postgres + redis + minio
pnpm db:migrate && pnpm db:seed
pnpm dev                      # web :3000, api :4000, docs :4000/docs
```

Щоб увімкнути справжній AI — `AI_PROVIDER=openai` + `OPENAI_API_KEY=sk-...` у `.env`.
Мок-режим повертає детерміновані, реалістичні дані, тому демо і e2e-тести працюють без витрат на токени.

## Що НЕ входить у MVP (свідомо)

Комісія з угод, безпечна оплата/ескроу, доставка, страхування, AI Exchange, мобільний застосунок.

Архітектура готова їх прийняти. Точки розширення вже в схемі: `Payment.feeKop` (комісія, зараз завжди 0),
`Listing.deliveryOptions`, `Listing.exchangeAccepted`, драйвер `push` у сповіщеннях,
а платіжний модуль абстрагований інтерфейсом `PaymentProvider` (на MVP — тільки підписки й просування).
Вмикається через `packages/config/feature-flags.ts` без міграцій.
